## 💡 공부한 내용 본인의 언어로 정리하기

### 1. 웹 서비스 전체 처리 흐름 (Lifecycle)
사용자가 웹페이지를 요청하고 화면을 보기까지의 과정은 **[사용자 요청] ➡️ [서버 처리] ➡️ [DB 데이터 처리] ➡️ [클라이언트 응답 및 렌더링]** 의 4단계를 거친다.

1. **사용자 요청 단계**: 브라우저에 URL 입력 ➡️ DNS 서버에서 IP 주소 조회 ➡️ 해당 서버로 HTTP/HTTPS 요청 전송
2. **서버 처리 단계**: Web Server가 정적 리소스를 전달하거나 WAS로 요청 위임 ➡️ Controller → Service → Repository 흐름으로 비즈니스 로직 수행
3. **데이터베이스 단계**: ORM/SQL 매퍼가 생성한 쿼리를 DB에서 실행 ➡️ 조회/수정 결과를 서버로 반환
4. **클라이언트 처리 단계**: 브라우저가 응답(JSON, HTML 등) 수신 ➡️ DOM 생성 및 CSS 스타일 적용, JS 동적 처리 ➡️ UI 최종 출력

---

### 2. Web Server vs Web Application Server (WAS)
정적 컨텐츠와 동적 로직을 처리하는 주체를 구분하는 것이 인프라 및 아키텍처 이해의 핵심이다.

- **Web Server (Nginx, Apache 등)**
  - HTML, CSS, JS, 이미지 등 **정적 리소스(Static Resource)**를 관리하고 클라이언트에 직전 전달
  - 필요에 따라 애플리케이션 서버(WAS)로 요청을 포워딩하는 역할
- **Web Application Server / WAS (Spring Boot, Tomcat 등)**
  - 비즈니스 로직 및 데이터 연동 등 **동적 리소스(Dynamic Resource)**를 처리하는 서버
  - Web Server 기능을 포함하며 Java 기반 환경(JSP, Servlet 등)을 실행

### 3. DB 접근 기술: ORM과 SQL Mapper (JPA vs MyBatis)
데이터베이스에 직접 SQL을 작성하는 방식에서 벗어나, 객체지향 언어와 RDBMS 간의 패러다임 불일치를 해결하기 위한 기술이다.

- **JPA (Java Persistence API)**
  - **특징**: 자바 진영의 표준 ORM 인터페이스 (구현체: Hibernate 등)
  - **장점**: SQL을 직접 작성하지 않고 객체 중심 코드(`userRepository.findById(1L)`)로 DB를 조작하여 생산성이 뛰어나고 추상화 수준이 높음
- **MyBatis**
  - **특징**: 엄밀히 말해 ORM보다는 **SQL Mapper**에 가까움
  - **장점**: SQL을 직접 작성하여 객체와 매핑해주므로 복잡한 쿼리나 SQL 최적화/제어가 필요한 환경에서 유연성이 높음

---

### 4. 주요 DBMS 분류 및 특징

| 구분 | 대표 DBMS | 벤더/제공자 | 주요 특징 |
| :--- | :--- | :--- | :--- |
| **오픈소스 RDBMS** | MySQL, PostgreSQL | Oracle, PostgreSQL Group | 가장 많이 활용되는 웹 표준 DB, PostgreSQL은 확장성과 기능성이 뛰어남 |
| **상용 RDBMS** | Oracle DB, MS SQL Server, DB2 | Oracle, Microsoft, IBM | 금융/대기업 및 메인프레임 환경에서 사용하며 높은 안정성과 보안 제공 |
| **NoSQL DB** | MongoDB, Redis, Cassandra | MongoDB Inc, Redis Labs, Apache | Document/In-memory/분산 DB 구조로 유연한 스키마, 캐싱 및 빅데이터 처리에 적합 |
