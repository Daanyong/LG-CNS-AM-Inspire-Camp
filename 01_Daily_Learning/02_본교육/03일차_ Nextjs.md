## 오늘 학습한 주제
- Next.js App Router의 폴더 기반 라우팅 및 중첩 레이아웃 구조
- Tailwind를 활용한 헤더/네비게이션 반응형 Flex 레이아웃 실습

## 오늘 배운 것 – 나만의 언어로 설명
- App Router의 폴더 기반 라우팅은 폴더 구조가 곧 웹사이트의 URL 주소가 되는 시스템이다. `(main)`, `(auth)` 같은 라우트 그룹을 활용하면 URL에 영향 없이 원하는 레이아웃을 효율적으로 분리할 수 있다.
- `layout.tsx`에 헤더나 푸터 같은 공통 UI를 둬서 페이지가 전환되어도 해당 영역이 리렌더링되지 않고 고정되도록 만들어 화면 전환 속도와 UX를 크게 높일 수 있다.
- CSS(`globals.css`)의 Flex 속성을 Tailwind CSS 클래스(`flex flex-row justify-between items-center gap-10`)로 1:1 매핑하며 이전하는 작업을 실습했다.
- `hidden md:flex` 및 `md:hidden` 같은 반응형 분기 처리를 활용해 모바일과 데스크톱 화면의 네비게이션을 깔끔하게 제어하는 프론트엔드 실무 패턴을 파악했다.

## 어려웠던 점 & 해결 과정
- 문제: 빠른 진행 속도 속에서 Next.js의 복잡한 폴더 구조와 Tailwind CSS의 방대한 유틸리티 클래스명이 한 번에 쏟아져 흐름을 자주 놓칠 뻔함
- 시도: 개별 유틸리티 클래스명을 하나하나 이해하고 넘어가려 하기보다는 CSS Flexbox의 주축/교차축 정렬 원리와 레이아웃 구조를 먼저 시각적으로 이해하려고 함
- 해결: `layout.tsx`가 페이지를 감싸는 상하 관계 및 데스크톱/모바일 반응형 분기점이라는 핵심 포인트에 집중해 전체 틀을 잡음
- 교훈: 정보량이 많고 지식이 쏟아질 때는 세부 문법보다 핵심 아키텍처와 정렬의 흐름을 빠르게 파악하는 것이 중요하다.
