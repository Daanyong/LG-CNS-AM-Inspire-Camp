## 오늘 배운 것 – 나만의 언어로 설명

## 1. 프로젝트 초기 설정과 다양한 개발 생태계
* 깃허브에 코드를 올릴 때 `node_modules` 폴더는 용량이 너무 크고 의존성 문제가 있기 때문에 `.gitignore`에 정의해서 빼고 올려야 한다고 배웠다. 
* `pnpm` 같은 패키지 매니저를 쓰면 락 파일이 생기는데, 개발자마다 환경이 달라서 패키지가 다르게 설치되어 충돌이 날 수도 있으니 조심하라고 하셨다.
* 요즘은 폴더블폰처럼 디바이스 화면이 플렉시블하게 변하는 경우가 많아서 프론트엔드 개발자들이 대응하기 점점 힘들어지고 있다고 한다.
* 웹 기술로 모바일 앱을 만드는 크로스 플랫폼 기술로 Flutter나 React Native가 있고, VS Code나 노션, 피그마 같은 데스크탑 앱들은 웹 기술을 패키징하는 Electron.js로 만들어졌다는 사실을 처음 알았다.
* PWA(Progressive Web App)를 사용하면 스토어에 앱을 올리지 않아도 웹에서 바로 앱처럼 바탕화면에 설치해서 쓸 수 있어서 아주 유용하다고 하셨다.
* 프론트엔드 취업을 하려면 남들이 많이 쓰는 대세 기술을 따라가는 게 중요한데, 요즘은 Tailwind CSS를 정말 많이 쓰고 컴포넌트 UI로는 Vercel이 인수해서 밀고 있는 shadcn/ui 같은 게 핫하다고 한다.

## 2. Next.js의 특징과 라우팅
* 리액트와 다르게 Next.js는 `index.html`이 겉으로 보이지 않고 `layout.tsx`와 `page.tsx`를 통해 화면을 구성한다.
* 예전에는 페이지 라우팅 방식을 썼지만 요즘은 앱 라우터 방식을 쓰며, `app` 폴더 안에 예를 들어 `about`이라는 폴더를 만들고 그 안에 `page.tsx`를 넣으면 알아서 `/about` 주소로 라우팅이 돼서 엄청 편했다.
* `layout.tsx`를 활용하면 페이지가 이동해도 헤더나 푸터 같은 공통된 부분은 다시 리렌더링되지 않아서 화면 전환이 엄청 빠르다.
* 만약 로그인 페이지처럼 헤더랑 푸터가 없어야 하는 화면이 있다면, 조건문을 쓰기보다 `(auth)`처럼 괄호로 묶은 그룹 폴더를 만들고 그 안에서 레이아웃을 따로 설정하면 주소창에는 영향을 안 주면서 레이아웃만 분리할 수 있다고 한다.

## 3. 사용자 경험(UX)과 미들웨어
* 로그인한 유저가 로그인 페이지에 또 접속하려고 할 때 어떻게 처리할지에 대한 UX 차이도 배웠다.
* 화면이 뜬 다음에 로그인된 걸 확인하고 리다이렉트 시키면 화면이 깜빡이거나 튕겨내는 게 눈에 보여서 별로 안 좋다고 한다.
* 넥스트는 서버 역할을 하기 때문에 미들웨어라는 걸 쓰면 클라이언트가 화면을 열기 전에 서버 단에서 로그인 여부를 체크하고 아예 로그인 페이지가 안 열리게 컷해버릴 수 있다고 한다.
* 그리고 JWT 토큰을 그냥 브라우저 로컬스토리지에 저장하면 보안상 위험할 수 있어서, 넥스트 서버 쪽에서 세션으로 가둬두고 관리하는 게 훨씬 안전한 방식이라고 강사님이 꿀팁을 주셨다.

## 4. Next.js 전용 컴포넌트와 폰트 적용
* 넥스트에서는 일반적인 `<img>` 태그나 `<a>` 태그 대신 전용 컴포넌트를 꼭 써야 한다.
* `<Image>` 컴포넌트를 쓰면 이미지가 로딩될 때 영역이 찌그러지는 걸 막아주고 용량 최적화도 알아서 해준다고 한다.
* `<Link>` 컴포넌트는 다음 페이지의 데이터를 미리 가져오는 프리패칭(Pre-fetching) 기능이 있어서 화면 이동이 진짜 앱처럼 빨라지는 걸 확인했다.
* 구글 폰트 같은 것도 외부 링크로 불러오는 게 아니라, 넥스트 안에서 폰트 변수를 선언해서 최상위 레이아웃 클래스에 넣어주면 전체 페이지에 한 번에 적용할 수 있어서 신기했다.

## 5. 아토믹 디자인 패턴과 컴포넌트 설계
* 코드를 짤 때 원자(Atom), 분자, 유기체, 템플릿, 페이지 단위로 컴포넌트를 잘게 쪼개는 아토믹 디자인 패턴을 직접 실습해봤다.
* 가장 작은 원자 단위인 타이틀 컴포넌트를 만들 때, 단순히 글자만 받게 만들지 않고 `children`을 사용해서 유연하게 만들었다.
* 태그 종류를 프롭스로 받아서 필요할 땐 H1으로, 어떨 땐 H3로 바뀌게 만들면 똑같은 컴포넌트를 여기저기서 막 쓸 수 있어서 진짜 효율적이라고 느꼈다.
* 테일윈드 클래스를 넘겨줄 때 우선순위 충돌이 날 수 있는데, 이럴 때 shadcn에서도 쓰는 `tailwind-merge` 같은 걸 활용하면 커스텀으로 넘긴 스타일을 우선 적용할 수 있다고 한다.

## 6. 반응형 CSS와 레이아웃 팁 (Flex vs Grid)
* 화면 양옆에 여백을 주고 가운데로 모으려면 테일윈드에서 `container` 속성과 `mx-auto`를 같이 쓰면 편하다.
* Flexbox를 쓸 때 제일 헷갈렸던 게 가로 세로 정렬이었는데, `flex-direction`이 `row`일 때랑 `column`일 때 `justify-content`랑 `align-items`가 움직이는 축이 아예 반대로 돌아간다는 걸 그림으로 설명해주셔서 겨우 이해했다.
* 모바일 화면과 데스크탑 화면에서 메뉴 모양이 아예 달라질 때 CSS로 억지로 껴맞추는 것보다, 아예 모바일용 컴포넌트랑 데스크탑용 컴포넌트를 두 개 만들어두고 화면 크기(md, lg 등)에 따라 `hidden` 처리해서 스위칭하는 게 실무에서는 훨씬 깔끔하고 유지보수하기 좋다고 하셨다.
* 2차원 표 형태가 필요할 땐 Grid를 쓰는데, 복잡한 반복문을 한 줄로 끝낼 수 있어서 리스트 페이지 같은 걸 만들 때 좋지만 평소엔 거의 Flex를 쓴다고 한다.
