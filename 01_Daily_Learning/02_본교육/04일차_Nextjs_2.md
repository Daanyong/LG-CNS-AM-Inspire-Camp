## 1. 아침 잡담 겸 개발자 현업 썰 (허스키와 기깃 플로우)

오늘 아침에는 남이 만들어 놓은 결과물만 보고 부러워하지 말고 그 밑에 깔린 무수한 노력과 기본기를 보라는 얘기를 들었다. 사람이나 코드를 볼 때 선입견을 갖는 게 진짜 무서운 거라 웬만하면 선입견을 줄이려고 노력해야 한다고 한다.

근데 현실은 팀 프로젝트 시작하면 소스 코드 때문에 헬게이트가 열린다. 혼자 코딩할 땐 아무 문제 없는데, 여러 명이 붙어서 작업하면 패키지 파일이나 코드 스타일, 린트 에러 때문에 개판이 된다. 

- 커밋하고 머지할 때 빌드 터지는 거 막으려고 허스키(Husky)라는 걸 깔아서 pre-commit, pre-build 체크를 거친다.
- 백엔드 애들은 도메인 단위로 깔끔하게 쪼개서 일하니까 충돌이 덜 나는데, 프론트엔드는 하나의 코드 베이스에 여러 명이 엉겨 붙으니까 패키지 파일이나 임포트 순서 한 줄 차이로도 미친 듯이 충돌이 난다.
- 깃 입장에서 A랑 B 타임라인 중에 뭐가 먼저인지 판단이 안 되니까 너네가 직접 고치라고 던져주는 게 충돌이다...
- 남의 코드 덮어씌웠다가 밤샘 야근하지 않으려면 팀 리더가 권한을 딱 쥐고 가이드라인이랑 깃 플로우(Git-flow) 정책을 개빡세게 잡아놔야 팀원들이 안 튀고 따라온다.(명심해야 함)

## 2. 자바스크립트 뇌절 방지용 개념 복습 (호이스팅, 미니피케이션, BOM)

### 호이스팅과 var의 빡침
호이스팅은 선언문이 최상단으로 끌어올려진 것처럼 동작하는 자바스크립트 특유의 기술이다.
- 옛날 var 쓰던 시절에는 밑에서 선언한 변수가 위로 덜컥 끌려 올라가는 바람에, 나중에 변수 재선언되고 값이 완전히 꼬여버리는 난리가 자주 났다.
- 2015년에 let이랑 const 나오고 나서야 이 멍청한(ㅋㅋㅋ) 스코프 오염 문제가 그나마 잡혔다.

### 미니피케이션 (min.js는 대체 왜 이따위로 생겼나)
우리가 오픈소스 받아보면 죄다 코드 가독성 일도 없이 한 줄로 쫙 붙어 있는 min.js 파일들이 있다.
- 개발자가 보기 좋게 띄어쓰기하고 길게 적어놓은 변수명을 a, b 같은 최단 길이 변수명으로 압축해버린 거다.
- 기계 입장에선 띄어쓰기 따위 필요 없고 쫙 붙여써야 파일 용량이 바이트 단위로 줄어들어서 웹 로딩 속도가 떡상한다.

### Async랑 Defer (HTML 파싱할 때 뻑나지 않게 하는 법)
HTML 읽다가 스크립트 태그 만나서 하얀 화면으로 멈춰있는 현상 막으려고 쓴다.
- Async: 다운로드 되자마자 HTML 파싱이고 나발이고 바로 스크립트 실행해버린다. 순서 꼬이기 딱 좋다.
- Defer: HTML 파싱 다 끝날 때까지 얌전히 백그라운드에서 다운만 받아뒀다가, DOM 다 만들어지면 그제서야 안전하게 실행한다. 넥스트나 기본 모듈에선 Defer가 기본빵이다.

### BOM (브라우저 정보 다 털어오는 법)
윈도우 객체(BOM) 쓰면 브라우저가 사용자 정보를 진짜 무서울 정도로 다 털어온다.
- window.innerWidth / innerHeight: 브라우저 창 크기 실시간으로 잰다.
- window.screen: 모니터 물리 해상도(1920x1080 등)랑 컬러 뎁스까지 다 뽑아온다.
- window.location: URL 주소 체계(href, host, pathname, port) 다 털어내고 강제로 주소 이동시킨다.
- window.navigator: 유저가 윈도우 쓰는지 맥 쓰는지, 크롬인지 사파리인지 유저 에이전트 다 읽어온다. 심지어 앱 네임 찍어보면 90년대 유물인 네스케이프(Netscape)나 모질라 개코(Gecko) 엔진 이름이 아직도 튀어나온다.

## 3. 리액트(CSR) 대 넥스트(SSR) 데이터 흐름 차이 

오늘 수업에서 제일 머리 터질 뻔했던 파트....복습 필수

### 리액트(CSR) 생각 방식
- 리액트는 상태가 먼저다. 
- 버튼 누르면 useState로 상태 2로 바꾸고, 그 2로 API 찔러서 데이터 가져오고 화면 새로 그린다. 
- 주소창 물음표나 파라미터는 화면 다 그려놓고 나중에 새로고침 대응하려고 억지로 갈아 끼우는 후순위 작업이다.

### 넥스트(SSR) 생각 방식
- 넥스트는 주소창이 먼저다.
- 서버 컴포넌트가 브라우저에 화면을 내려주기 전에 주소창에 박힌 파라미터나 쿼리 스트링을 제일 먼저 쓱 읽는다.
- 주소창 정보를 가지고 서버에서 미리 API 찔러서 데이터를 완성한 다음에, 완성된 HTML 덩어리를 클라이언트에 던져준다.
- 리액트 때 쓰던 습관대로 넥스트에서 유즈스테이트 써서 주소 바꿀 생각 하면 하이드레이션 터지고 에러 메시지 폭탄 맞는다. 넥스트에서는 주소를 라우터 푸시로 바꿔서 서버가 알아서 주소 쥐고 데이터 새로 그리게 만들어야 된다.

## 4. 넥스트 동적 라우팅 삽질기 (Params & SearchParams)

### 패스 파라미터 (Params)
- 폴더 이름을 `[id]` 나 `[slug]` 처럼 대괄호 쳐서 만든다.
- `/blog/123` 이렇게 들어오면 페이지 컴포넌트 프롭스로 들어오는 params를 async/await로 풀어서 123을 꺼낸다.
- 보통 DB에 있는 아이디값이나 개별 글 상세 페이지 렌더링할 때 쓴다.

### 쿼리 스트링 (SearchParams)
- 주소 뒤에 `/feed?page=2&limit=100` 처럼 물음표 뒤에 키-값으로 들어오는 놈들이다.
- searchParams 프롭스로 읽어오는데, 사용자가 주소창에 이상한 쓰레기 쿼리 키를 쳐넣어도 우리가 정해둔 키값만 쏙 뽑아서 쓰면 되니까 에러 안 난다.
- 쇼핑몰 상품 검색, 필터링, 정렬, 무한 스크롤 페이징 처리할 때 미친 듯이 쓴다.

### 중첩 동적 라우팅 (Catch-all Segments)
- 폴더명을 `[...categoryName]` 처럼 점 세 개 찍어서 스프레드 연산자로 선언한다.
- `/product/clothes/top/shirts` 처럼 뎁스가 아무리 깊게 들어와도 배열로 싹 다 긁어모아 준다.
- 카테고리 네임이 배열로 들어오니까 `array.join('/')` 쳐서 상단 브레드크럼 만들거나 뎁스별 카테고리 칠 때 편하다고 한다.

## 5. 서버 컴포넌트랑 클라이언트 컴포넌트 쪼개기 & 서스펜스

- 서스펜스(Suspense): 동적 주소 받아서 데이터 가져오는 동안 화면이 하얗게 랙 걸린 것처럼 보이면 유저들 빡치니까 완충제로 서스펜스 박고 로딩 바나 스켈레톤 UI를 띄워준다.
- 컴포넌트 쪼개기: 데이터 패칭하고 뼈대 잡는 건 무조건 서버 컴포넌트로 놔두고, 버튼 클릭(onClick)이나 라우터 푸시(useRouter) 같은 진짜 유저 손가락 액션이 필요한 최하단 버튼 단위만 따로 떼어내서 맨 위에 'use client' 붙여서 쓴다.
- 서버에서 주소 읽어오고 -> 자식 클라이언트 컴포넌트로 값 넘기고 -> 클릭하면 주소만 푸시해서 새로 그리게 만드는 이 넥스트 스타일 패턴을 몸에 익혀야 헛짓거리를 안 한다.
