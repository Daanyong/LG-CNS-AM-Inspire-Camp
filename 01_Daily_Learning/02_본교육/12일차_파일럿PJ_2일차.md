# [Day 12] LG CNS AM Inspire Camp 7기 TIL
작성일: 2026.11.11 (수) | 과목: AI 서비스 개발을 위한 프론트엔드

## 오늘 학습한 주제
- 파일럿 프로젝트 개발 2일차

## 오늘 한 일 
- React와 Styled-components를 활용한 레시피 작성 페이지(RecipeWritePage.jsx)의 핵심 등록 로직 및 UI 구현

- 프론트엔드에서 입력한 데이터(텍스트, 식재료, 해시태그, 이미지 등)를 서버가 원하는 규격(Payload)으로 가공하여 전송하는 기능 완성

- Swagger를 통해 백엔드 API 명세와 실제 DB ID(foodTypeId, categoryIds) 구조를 확인하고 데이터 매핑 작업 진행

## 주요 트러블슈팅 & 배운 점
1. 식재료 데이터 구조 꼬임으로 인한 400 (Bad Request) 에러 해결

  - 원인: 모달에서 가져온 식재료 객체 배열을 서버로 보낼 때, 객체가 중복으로 감싸져 있거나 고정값(ingredientId: 0)으로 들어가 서버 규격과 어긋남.

  - 해결: selectedIngredients.map()을 통해 백엔드가 요구하는 정확한 형태인 { ingredientId, name, quantity } 구조로 데이터를 매핑하여 전송하도록 수정함.

2. 프론트엔드 UI 텍스트와 백엔드 DB ID 매핑

  - 원인: 사용자는 화면에서 "한식", "간식·디저트" 같은 텍스트를 선택하지만, 서버는 각각 고유한 숫자 ID(foodTypeId, categoryIds)를 요구하여 유효성 검사 에러가 발생함.

  - 해결: Swagger(GET /api/v1/food-types, GET /api/v1/categories)를 통해 서버에 저장된 실제 ID 목록을 확인하고, 사용자의 선택값을 올바른 숫자 ID로 변환해 주는 매핑 함수를 작성하여 해결함.

3. Git & GitHub PR 및 AI 리뷰어 활용

  - 구현 완료된 코드를 Git을 통해 원격 저장소에 푸시(push)하고 Pull Request(PR)를 생성함.

  - CodeRabbit(코드래빗) AI 리뷰어를 통해 작성한 레시피 등록 폼과 유효성 검사 로직에 대한 요약 및 피드백을 확인하며 PR 협업 프로세스를 경험함.
