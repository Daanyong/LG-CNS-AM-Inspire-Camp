## 💡 공부한 내용 본인의 언어로 정리하기

### 1. 웹 서비스 동작의 큰 그림 (클라이언트 - 서버 - DB)
웹 서비스는 식당의 손님, 웨이터, 주방장의 관계와 같다.
- **클라이언트 (Client)** : 사용자가 눈으로 보는 영역(브라우저, 앱 화면). 식당의 손님에 비유할 수 있다.
- **서버 (Server)**: 요청을 받아서 실제로 로직을 처리하고 결과를 돌려주는 백엔드 영역. 주문을 받고 음식을 전달하는 서비스 창구 역할을 한다.
- **데이터베이스 (DB)**: 데이터가 안전하게 저장되어 있는 창고. 회원 정보, 게시글, 주문 내역 등이 보관되어 있다.

> **데이터 흐름 summary**:  
> 사용자가 버튼 클릭/입력 ➡️ **요청(Request)** 전달 ➡️ 서버에서 로직 처리 및 DB 조회 ➡️ **응답(Response)** 전달 ➡️ 브라우저 UI 화면 표시

---

### 2. 서비스 주요 처리 흐름 5단계
1. **사용자 입력**: 로그인, 글 작성, 상품 검색 등 클라이언트 측에서의 행동
2. **요청 전달 (HTTP Request)**: 브라우저가 서버에 "이 작업 처리해줘"라고 메시지 전송
3. **서버 처리**: 서버가 요청을 해석하고 필요시 DB에서 데이터를 조회/수정하는 로직 수행
4. **응답 반환 (HTTP Response)**: 처리된 결과를 다시 클라이언트로 반환
5. **화면 표시**: 전달받은 응답 데이터를 브라우저가 UI 형태로 변환하여 사용자에게 제공

---

### 3. 기획/개발 관점에서의 주요 개념 정리
- **프론트엔드 (Front-End)**
  - HTML, CSS, JavaScript, React, Vue 등을 활용해 사용자가 접하는 화면을 구축
  - UI/UX 설계와 직접 직결되며, 사용자 경험을 결정짓는 핵심 영역
- **백엔드 (Back-End)**
  - Spring Boot, Node.js, Django 등으로 비즈니스 로직 및 서버 환경 구축
  - 요청과 응답 과정에서 어떤 데이터를 주고받을지(Data Flow) 정확히 정의해야 함
- **데이터베이스 (DB)**
  - MySQL, PostgreSQL 등을 통해 데이터 간의 관계(Relation)를 정의하고 체계적으로 관리
- **API (Application Programming Interface)**
  - 프론트엔드와 백엔드가 서로 통신하기 위해 약속한 규약
  - 주로 **JSON** 형태로 데이터를 주고받으며, Swagger 등의 명세서 도구를 통해 개발자 및 기획자 간 원활한 소통을 진행함
